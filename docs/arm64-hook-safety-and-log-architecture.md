# ARM64 Inline Hook Safety & Android Logging Architecture

## 1. Context & Motivation

During on-device testing on Android 17 / API 37 (`SM-S931N`), *Revolution Idle* (`com.oninou.revolution`, Unity 2022.3.62f3) crashed on launch with `SIGSEGV (SEGV_ACCERR)` in `libc.so (__memset_aarch64_nt)` called via `mono_class_get_checked`, while *The Tower* (Unity 6000.3.15f1) launched without issues. The legacy launcher version (`com.bepinex.android`) launched both games without crashes.

Investigation of memory offsets, Dobby trampolines, and disassembled binaries revealed two core architectural gaps:
1. **Unbounded Inline Hooking on ARM64**: Dobby writes 16-byte inline branch trampolines (`LDR X16, #8; BR X16; <addr>`). When a detour targets a 4-byte branch stub (`B target`) or an address immediately preceding a function epilogue (`LDR X30, [SP], #0x10; RET`), the 16-byte patch stomps past the function boundary, corrupting adjacent jump stubs and instruction bytes of subsequent functions.
2. **Redundant Android Logging Configuration**: Upstream desktop BepInEx defaults `UnityLogListening = true`, hooking Unity's managed `Application.s_LogCallbackHandler` via `ClassInjector` at startup. On Android, Unity natively emits all engine logs directly to system Logcat under the `Unity` tag, making managed log forwarding redundant and unnecessarily forcing early `ClassInjector` setup on vanilla boots.

## 2. Architectural Decisions

### ADR 7: Universal Thunk Resolution in `NativeDetour`
* **Context**: `ExportThunkResolver` was previously invoked only for `il2cpp_runtime_invoke` inside `IL2CPPChainloader`. Injected hooks generated by `Il2CppInterop` (such as `MetadataCache::GetTypeInfoFromTypeDefinitionIndex` at `0x1b6d540: b 0x1afd6dc`) directly passed 4-byte jump stubs to `NativeDetour`, causing Dobby to overwrite neighboring jump stubs (`0x1b6d544`, `0x1b6d548`).
* **Decision**: Wire `ExportThunkResolver.Resolve(target, "NativeDetour")` into the `NativeDetour` constructor for all native hooks.
* **Invariant**: No native detour may attach to a forwarding branch stub. All detours must resolve to the definitive function body.

### ADR 8: AArch64 Inline Hook Space Guard
* **Context**: An AArch64 inline hook requires 16 bytes (4 instructions). If an address has fewer than 16 bytes before a `RET` instruction (e.g. `0x1b5e81c` with `RET` at `+4`), writing 16 bytes corrupts the subsequent function in memory.
* **Decision**: Implement `ExportThunkResolver.CanSafelyHook(target, out reason)`. On ARM64, verify that none of the instructions in the first 16 bytes (`target + 0`, `+4`, `+8`, `+12`) is `RET` (`(opcode & 0xFFFFFC1Fu) == 0xD65F0000u`). If violated, `NativeDetour` throws `InvalidOperationException`.
* **Outcome**: Caught cleanly by `Hook.ApplyHook()`, which logs `Target hook method not found` and safely skips the hook instead of corrupting executable memory.

### ADR 9: Android Native Logcat Decoupling
* **Context**: On Android, Unity logs already stream to Logcat (`Unity` tag), and BepInEx logs stream to Logcat (`BepInEx` tag via `AndroidLogListener`). Setting `UnityLogListening = true` duplicates Unity messages in Logcat and triggers early `ClassInjector` startup before plugins load.
* **Decision**: Set `UnityLogListening = false` as default in `BepInEx.cfg` and `IL2CPPChainloader.cs`.
* **Outcome**: Eliminates duplicate log traffic and ensures vanilla game boot does not trigger unnecessary interop hooking.

### ADR 10: Il2CppInterop Heuristic Sanitization
* **Context**: On ARM64 Unity 2022.3, `FindClassGetFieldDefaultValueXref()` in `Class_GetFieldDefaultValue_Hook.cs` traversed across tail-call branches into an epilogue (`0x1b5e81c`).
* **Decision**: Validate resolved hook addresses: ensure the candidate is non-null, 4-byte aligned, and contains no `RET` within the first 16 bytes. If validation fails, return `IntPtr.Zero` to trigger standard `TargetMethodNotFound()` handling.
* **Outcome**: Parity with Unity 6 fallback behavior, preventing bad pointer generation.

### ADR 11: Il2CppInterop `MetadataCache` Hook Exclusion on Android
* **Context**: When plugins call `ClassInjector.RegisterTypeInIl2Cpp`, `InjectorHelpers.Setup()` installed `MetadataCache_GetTypeInfoFromTypeDefinitionIndex_Hook`. On Unity 2022.3+ (Metadata v29+), `GetTypeInfoFromHandle` targets `il2cpp::vm::MetadataCache::GetTypeInfoFromTypeHandle(Il2CppTypeDefinitionHandle handle)` which takes a 64-bit struct pointer in `X0`. The hook delegate `Il2CppClass* MethodDelegate(int index)` treated `X0` as a 32-bit integer, zero-extending it upon forwarding to `Original(index)` and wiping the high 32 bits (e.g. `0x00000079502434c0` -> `0x00000000502434c0`), resulting in fatal `SIGSEGV (SEGV_MAPERR)` at `0x502434c0` (`ldr x8, [x0, #0x28]`). The legacy Android fork never registered this hook in `InjectorHelpers.Setup()`.
* **Decision**: Remove `GetTypeInfoFromTypeDefinitionIndexHook.ApplyHook()` from `InjectorHelpers.Setup()`, aligning with the legacy Android fork. Dynamic type injection uses `InjectedAssembly` where classes are resolved via `FromIl2CppTypeHook` and `FromNameHook`.
* **Outcome**: Eliminates pointer truncation segfaults when mods inject custom `MonoBehaviour` types on Unity 2022.3+.

### ADR 12: BootstrapActivity Configuration Changes & State Preservation
* **Context**: On display topology changes or device rotation during game startup, Android destroyed and recreated `BootstrapActivity`. Because `isGameLaunched` was set early in `onCreate`, the recreated instance falsely assumed an existing game was already running in `:game`, scheduled an `AlarmManager` pending intent to restart, and terminated the process (`System.exit(0)`). On modern Android (API 34+), Background Activity Launch (BAL) blocked the pending intent, leaving the app closed.
* **Decision**:
  1. Add full `android:configChanges` to `BootstrapActivity` in `AndroidManifest.xml`.
  2. Skip bootstrap logic if `savedInstanceState != null`.
  3. Set `isGameLaunched = true` only upon launching `StubActivity`.
  4. Preserve `SCREEN_ORIENTATION_UNSPECIFIED` instead of coercing to landscape when the target game does not specify orientation.
* **Outcome**: Prevents race conditions and unintended process restarts on orientation changes for games like *The Tower*.
