# Enforced by launcher/scripts/verify_prebuilts.sh on files staged into
# launcher/app/src/main/jniLibs and launcher/app/src/main/assets (never
# committed; see .gitignore). Each hash pins the exact artifact built from the
# pins in provenance/*.env. Rebuilds from the same pins emit identical bytes:
# native builds strip path-carrying debug info (see scripts/build_native_deps.sh),
# the runtime pack is a deterministic repack of the pinned pack
# (see scripts/fetch_dotnet_runtime.sh), and the framework zip pins its epoch
# to the upstream pin's commit date while the compiler's SourceRevisionId is
# the upstream pin (see scripts/package_bepinex_android.sh,
# scripts/restore_and_build.sh). A hash changes only when a pinned input is
# deliberately bumped; rebaseline from a trusted CI build with
# launcher/scripts/verify_prebuilts.sh --update-manifest, never by hand.
# See provenance/SOURCES.md for what the manifest does and does not prove.
#
# BepInEx.Android.zip is deliberately NOT listed here. The framework zip is
# built from the patched tree plus freshly rebuilt MonoMod/Il2CppInterop
# packages, and those upstream builds are not byte-reproducible across
# machines (measured 2026-10-13: same sources, same pins, three CI runs
# produced three different zips; the MonoMod.Core.dll alone differed by 77%
# of its bytes). No static hash can ever match it. Its integrity is verified
# instead by the patch gate (sources), the version gate (dependencies), the
# feed consistency checks in scripts/package_bepinex_android.sh, and the
# producer attestation - all of which run before this manifest is checked.
